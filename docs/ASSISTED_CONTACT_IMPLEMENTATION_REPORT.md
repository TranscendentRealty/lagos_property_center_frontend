### What the feature does

- **Manual help everywhere.** A "Get a shortlist" action appears in the navigation, the footer, the floating contact group and listing pages ("Help me find similar properties"). Each one opens the same two-step form in a drawer, with `/get-a-shortlist` as a real fallback page.
- **Truthful empty searches.** Search now has explicit `idle`, `success` and `error` states. The inline shortlist offer appears only when a search succeeded and its total is genuinely zero, in both standard and AI search.
- **Durable intake.** The form posts to a same-origin Next route. That route validates the request and forwards it, with a server-only secret, to a new Express intake. The intake stores a `Lead` in MongoDB with idempotency, duplicate linkage, rate limits and an embedded notification job, which a retrying worker sends through Resend.
- **Agent register.** The admin client gains a Leads list and a detail page with workflow stages, owner, next action, notes, history and notification retry.
- **Proactive experiment (Release B, off by default).** A nonmodal panel appears after two distinct listing views AND 90 seconds of estimated active browsing. It uses a 50/50 treatment/control split, cross-tab coordination and a seven-day cooldown.
- **Contact form.** First name is optional, the visitor picks one preferred channel, and a message is required. It uses durable intake when that is configured; otherwise it falls back to the legacy email path, with HTML escaping fixed.

### Your revisions, applied

1. **No rent anywhere.** There is no buy/rent question or field in the form, the data contract, the database or the copy. The intake rejects a `transactionType` key as unsupported.
2. **No budget.** There are no bands, no custom minimum or maximum, and no "Other budget" option. A listing's price is never copied into a request. The intake rejects `budget` and price keys. The plan's offer copy changed from "area and budget" to "area and type of home".
3. **Consent repair skipped.** `readConsent()`, `consentValues()`, `initializeMeasurement()`, the commented-out consent modal and the footer preferences button are untouched. `eventNames` and `parameterNames` in `measurement.ts` were extended. New code reads consent only through `readConsent()`, so it will respect real choices as soon as you restore that function.
